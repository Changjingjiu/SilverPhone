## 二、可以直接复制给执行 AI 的总控提示词

> 你要为我实现一个仅面向 Android 手机的“SilverPhone”应用。请先完整阅读我提供的四份 Markdown 文档。
>
> 日常用户是可能不识字、视力不好、不熟悉手机操作的老人。家属负责设置。老人平时只需要找到醒目的桌面 App 图标、打开应用、看照片找到亲人、单击照片卡片发起普通电话。
>
> 必须使用 Kotlin、Jetpack Compose、Room。按文档实现本地联系人、照片、全局字体大小、系统通讯录批量导入，以及包含照片的联系人文件导出和导入。默认最低 Android 6.0 / API 23，不能偷偷抬高最低版本。
>
> 这是一个范围明确的小型工具。不要添加账号、服务器、云同步、聊天、视频通话、定位、广告、支付、AI 助手、复杂角色权限、自定义通话系统、默认拨号器接管或老人桌面。
>
> 正常条件下，老人点一张照片卡只触发一次拨号请求。不得每次要求确认、长按、双击或再次选择号码；不得把“打开系统拨号盘但还需按拨号键”冒充完整的一步拨号。系统权限、双卡选择、紧急号码处理及运营商限制必须如实说明。
>
> App 负责发起电话，系统电话界面负责接通、取消呼叫、挂断、免提等通话控制。不要画出无法真正生效的“挂断”按钮，也不要声称能够统一厂商电话界面的颜色与字号。
>
> 实施前先输出一张简短的需求映射表：功能编号、对应页面、核心逻辑、计划验证方式。然后按阶段交付可以运行的应用，每个阶段都保持已有能力可用。不要只输出计划、伪代码、静态截图或无功能按钮。
>
> 遇到普通实现细节，按文档的默认决定执行。只有文档相互冲突、涉及真实签名身份或实际目标设备不满足 API 23 时，才提出具体问题。不要借提问重新发散产品范围。不能实现的要求必须标明原因与影响，不得静默删掉。
>
> 最终提交完整工程、可安装 APK、构建说明、测试记录和已知限制。测试记录必须区分自动测试、模拟器与真机；没有执行过的验证不能写成通过。未经另行授权，不发布到商店、不上传真实联系人、不对外发送文件。

## 三、用户原始要求与补充决定的边界

### 3.1 用户明确提出的要求

- 安卓专用；Kotlin 编程；Jetpack 界面；Room 数据存储。
- 界面字体大、清楚；图标大；排列整齐。
- 点某个亲人的照片或图标，就给该亲人打电话。
- 可自定义亲人照片、电话号码、显示名字。
- 支持联系人导出、跨手机传递和导入，减少家属重复录入。
- 照顾不识字、不熟悉操作的老人；点击逻辑简单、容易学。
- App 桌面图标颜色醒目、方便辨认和记忆，并尽量避免与目标手机上常见 App 混淆。
- 界面通过颜色和图形帮助理解，拨打和取消等操作区分明确。
- 支持整体字号放大和缩小，并保持布局清楚。
- 兼容低版本 Android。

### 3.2 为保证可执行而补充的默认决定

以下是本套文档的统一默认值，不应伪称为用户已逐项指定：

| 决定 | V1 默认规则 | 原因 |
|---|---|---|
| 产品名称 | SilverPhone | 应用名、工程名、仓库名、包名统一用 SilverPhone，不再另起别名 |
| 最低系统 | Android 6.0，API 23 | 兼顾旧设备与当前 AndroidX / Room 路线 |
| UI 实现 | Jetpack Compose + Material 3 基础组件 | 将“Jetpack 界面”具体化 |
| 拨号方式 | 点卡后使用 ACTION_CALL 请求系统拨号 | 与点照片直接打电话一致 |
| 通话边界 | 不接管系统通话界面 | 避免引入默认拨号器权限和通话框架复杂度 |
| 首页结构 | 一屏亲人卡片，最多两列，纵向滚动 | 只教一种浏览方式，不加底部多栏目 |
| 家属入口 | 点“家属设置”，再点“进入设置” | 防止误入，同时不要求秘密手势或密码 |
| 字号档位 | 标准 1.0、大 1.2、特大 1.4、超大 1.6；默认大 | 可调大、可从大调小，最小档仍然清楚 |
| 本地数据容量 | 最多 500 张联系人卡 | 有界输入，方便旧机内存与备份验证 |
| 一张卡的号码 | 一个明确的拨号号码 | 避免老人点击后再选择 |
| 联系人顺序 | 家属手工排列，固定保存 | 不用频次算法打乱老人记忆 |
| 同号联系人 | 允许；手工保存时提醒，文件追加导入时按固定规则跳过已有号码 | 兼顾共用座机与避免跨机重复 |
| 系统通讯录 | 提供家属批量导入入口，只读、不回写 | 覆盖“手机上已经有很多联系人”的情形 |
| 文件格式 | 普通 ZIP 容器，内含 manifest.json 与照片；协议版本 1 | 一个文件传完，不依赖另一台手机的路径 |
| 导入默认模式 | 追加，保留当前手机已有信息 | 两位老人对同一个人的称呼可能不同 |
| 替换导入 | 明确选择与再次确认后，整体替换联系人 | 满足完整复制需求，避免意外覆盖 |
| 配色 | 固定高对比浅色；关闭动态取色；不新增夜间主题开关 | 维持老人已经学会的颜色和位置 |
| 桌面图标 | 荧光黄绿色底 #D6FF00，深墨蓝 #172554 粗听筒 | 提供醒目的颜色加轮廓；不承诺市场唯一 |
| 语音与联网 | V1 不做语音助手、云功能或广告 | 聚焦照片拨号闭环 |

如果后来明确必须覆盖 Android 5.x，需要重新制定整套依赖及设备验证方案。不得只把 minSdk 改为 21，或使用 manifest overrideLibrary 绕过依赖限制。当前文档不包含 Android 5.x 的兼容承诺。AndroidX 当前默认 minSdk 与 Room 2.8 系列的最低版本说明可见：[AndroidX 版本说明](https://developer.android.com/jetpack/androidx/versions)、[Room 发布记录](https://developer.android.com/jetpack/androidx/releases/room)。

## 四、不可偏离基线

- **B01**：核心任务是照片拨打普通电话，打开首页后一次普通点击发起请求。
- **B02**：老人首页不承载编辑、删除、排序、导入导出和字号设置。
- **B03**：真人照片优先；姓名、颜色、听筒轮廓共同辅助识别；不能只依赖文字或红绿颜色。
- **B04**：所有联系人字段、照片与顺序必须持久保存；禁止只存临时 URI。
- **B05**：交换文件必须包含照片实际内容，导入后断开与原手机的一切联系仍能显示。
- **B06**：追加导入保留目标机已有称呼、照片、号码与位置；只增加未匹配项。
- **B07**：联系人及照片作为一个数据库事务提交；任何失败不能留下半份导入结果。
- **B08**：字号先服从系统无障碍设置，再使用应用档位；空间不足时重排或滚动，禁止强制缩小。
- **B09**：App 无法保证系统电话界面、桌面主题和系统文件选择器受自身控制。
- **B10**：最低 API 23；升级依赖不得自动提高它。支持目标旧系统是产品需求，不属于要删除的历史代码兼容层。
- **B11**：只实现当前协议和当前产品路径，不加旧版格式适配、历史数据库迁移框架或隐藏回退路线。
- **B12**：不使用“迁移失败后清空数据库”来掩盖错误；保留数据并给出明确失败信息。
- **B13**：导出的文件默认未加密；由家属选择保存或分享；只在相应操作页面简短提示其中含姓名、号码、照片。
- **B14**：真实拨号、真实设备兼容性和老人可用性均需要对应证据；不能从编译成功推断。

## 六、交给不同 AI 时的任务结尾

### 只做 UI 时

> 依据 01 文档完成全部页面与状态设计；用 02、03 核对交互是否真实成立。输出页面清单、视觉变量、各尺寸布局和异常状态。不得更改拨号流程或扩展功能。本轮不要编造已经实现的 APK。

### 做业务逻辑时

> 依据 02 文档实现业务规则，保持 01 页面行为和 03 验收目标不变。优先验证一次点击只拨一次、照片持久化、重复导入、取消与失败原子性。输出可测试的代码和对应结果。

### 做完整应用时

> 四份文档全部执行。先跑通最小可用拨号闭环，再加入管理、通讯录导入、ZIP 交换和字号适配。最终交付工程与可安装 APK，不以源代码压缩包代替 APK。

### 做独立验收时

> 按 03 的验收编号逐条检查，并交叉核对 02 的边界输入。标注通过、失败、未验证，附设备/API/构建类型及证据路径。不要仅凭阅读代码或截图宣布真实电话拨打成功。

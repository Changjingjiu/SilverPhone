# 01｜老人亲人拨号 App：UI 设计 AI 提示词

版本：1.0｜日期：2026-09-17｜产品名：SilverPhone
配套：[总控](00_使用说明与总控提示词.md) · [软件逻辑](02_软件逻辑_AI提示词.md) · [软件功能](03_软件功能_AI提示词.md) · [技术栈](04_软件技术栈_AI提示词.md)

## 1. 给执行 AI 的角色与任务

你是一名熟悉 Android、Jetpack Compose、低识字用户与老年人无障碍需求的产品 UI 设计师。请依据本文设计一个**看照片、点一下、给亲人打普通电话**的应用。

不要把任务理解为普通通讯录换大字号。老人可能不认识任何字，也不懂齿轮、菜单、双击、长按、左右滑动、更多按钮等约定。核心流程必须由真人照片、明确形状、固定位置和一次点击共同支撑。

请完成全部页面及状态，并提供能被 Kotlin / Compose 开发直接实现的尺寸、颜色、组件和行为。不能只画一张漂亮首页。不自行增加功能，不改成网页、Flutter、聊天应用或系统拨号器。

## 2. 必须先记住的产品事实

1. 日常使用者是老人；家属承担录入、修改、导入导出与调整字号。
2. 一张亲人卡片对应一个确定的电话号码。
3. 点照片、姓名或绿色拨打区域，触发同一个拨号动作。
4. 正常拨号不增加本应用的确认页、倒计时、长按、双击或号码选择。
5. 拨号成功交给系统后，取消呼叫、挂断和免提由系统电话页面完成。
6. 所有核心资料保存在本机；启动、浏览、管理不要求联网或登录。
7. 最低 Android 6.0 / API 23 是文档默认基线，不能假定全部用户都有新手机。
8. 联系人上限 500；典型家庭可以只有 4～12 位。不能为了显示 500 位而把所有卡片做小。
9. 字号默认“大”，可调小或继续调大；同时尊重系统字号。
10. V1 采用固定高对比浅色主题，不跟随壁纸动态改变拨号色，不提供皮肤市场或主题列表。

## 4. 视觉方向：熟悉的照片电话本

- 老人首先看见亲人的脸；其次看见称呼；最后看见绿色听筒和“拨打”。
- 首页主要面积用于亲人卡片，不用于品牌宣传、大面积插画和使用说明。
- 一个组件只能表达一种主行为。卡片上的照片不能进入详情，而底部按钮才打电话。
- 用明显边界和留白分隔相邻亲人，防止手指碰到旁边的人。
- 保持排序、颜色含义和页面结构稳定。刷新、重启、通话返回不能随机换位。
- 不用玻璃拟态、渐变背景、低对比灰字、装饰性光效、动态头像或不断跳动的提示。

## 5. 颜色规范

### 5.1 固定颜色变量

实现时集中定义语义颜色，不在各页面随意另选近似值。

| 语义变量 | 颜色 | 用途 |
|---|---|---|
| BrandLime | #D6FF00 | 桌面图标背景、小面积品牌记忆点 |
| Ink | #172554 | 主要文字、粗听筒、主要管理操作 |
| Background | #F7F8FA | 页面背景 |
| Surface | #FFFFFF | 卡片、表单、对话框 |
| TextPrimary | #172554 | 主要文字 |
| TextSecondary | #475569 | 帮助说明；仍须清楚可读 |
| CallGreen | #146C43 | 拨打区域、电话相关主行动 |
| OnCallGreen | #FFFFFF | 绿色区域里的文字与听筒 |
| CancelRed | #B42318 | 取消的文字、叉形图标与描边 |
| DangerRed | #B42318 | 删除、整体替换的实心危险按钮 |
| Outline | #64748B | 必须可辨的输入框和按钮边界 |
| Focus | #1D4ED8 | 键盘／无障碍焦点描边 |

配色是本方案的设计选择；执行 AI 必须验证实际前景／背景组合的对比度。文字统一以至少 4.5:1 为目标；关键图形、焦点与控件边界至少 3:1。照片本身不作文字底图。

本次已对静态色值进行计算：深墨蓝听筒／荧光底约 12.71:1，白字／拨号绿约 6.45:1，取消红／白底约 6.57:1，辅助文字／页面底约 7.13:1。这只是色值计算，实际透明度、禁用样式、图片叠加和焦点显示仍需在实现后验证。

### 5.2 操作颜色规则

- **拨打**：绿色实心区域 + 实心听筒 + “拨打”。
- **取消当前操作**：红色描边 + 叉形 + “取消”。取消保持原数据。
- **删除或全部替换**：红色实心 + 垃圾桶／明确替换图标 + 精确动作文字；必须确认。
- **保存／导入／进入设置**：深蓝实心 + 对勾／对应图形 + 动作文字。
- **返回上一级**：深蓝箭头 + “返回”，不与删除按钮混用。

“取消”和“删除”即使都用红色，也必须通过图形、实心／描边、文字和位置区分。不能用两个视觉完全相同的红色按钮并排表达相反结果。小屏或大字时两个动作纵向排列；默认焦点放在非破坏性动作。

### 5.3 颜色不能承担全部含义

把页面转换为灰度后，用户仍应能通过照片、听筒、叉号、箭头和文字区分动作。不能靠“点绿的、别点红的”作为唯一说明。联系人之间以照片为主识别，不随机给每个人整张卡片涂鲜艳颜色。

## 6. App 桌面图标设计

### 6.1 唯一主方案

- 满底采用荧光黄绿色 #D6FF00。
- 中央采用深墨蓝 #172554 的**粗实心传统电话听筒**，大、简单、轮廓完整。
- 不在图标里放“SilverPhone”四个字，不使用多个小头像拼贴，不放字母缩写。
- 不增加通知角标、红点、装饰性小星星、细线外框或照片纹理。
- 图标主体形状在彩色、灰度、单色主题下都应能认出来。
- 桌面名称“SilverPhone”，但不能要求老人必须认出这四个字才能找到图标。

“荧光”是数字颜色的视觉描述，不代表屏幕能发出真实荧光。也不宣称该颜色只有本应用使用。应把方案放进目标手机实际安装的图标群中检验，尤其与系统电话、微信及其他黄色／绿色图标比较。

### 6.2 资源与形状

- Android 6～7：提供标准 mipmap 位图密度资源。
- Android 8+：提供 adaptive icon 的前景与背景。
- 支持的主题图标场景：提供相同听筒轮廓的 monochrome 资源。
- 自适应图标使用 108 × 108 dp 图层，关键听筒位于中央 66 × 66 dp 安全区域；至少验证圆形、圆角方形等遮罩。
- 不把不可裁切的关键信息放在边角。
- 输出正常桌面尺寸、缩略尺寸、灰度及不同遮罩预览。

Android 的图标形状与主题可能由启动器改变，系统也可能进行单色处理。App 不能保证图标永远保持指定颜色，也不能自行强制放大桌面图标。家属设置说明应提醒：可把应用放在桌面固定位置，并在设备允许时调大桌面图标、关闭会造成混淆的主题图标。不要申请悬浮窗或改造启动器解决这个问题。[官方图标规范](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)

## 7. 字体、图形与触控尺寸

### 7.1 字体原则

- 使用系统支持的无衬线中文字体；不下载字体，不附带大型商业字体包。
- 全部可读文字使用 sp；布局与触控区域使用 dp。
- 姓名及主要动作使用 Medium 或 Semibold，不用细字重。
- 不以自动缩字、横向跑马灯或省略号解决姓名显示问题。
- 长名字允许换行并撑高容器；老人首页不截断辨认所需内容。
- 全局调整包括首页、设置、输入框、对话框、错误说明及操作按钮；系统自带页面不受本应用档位控制。

### 7.2 字号基准

下表为应用倍率 1.0 时的基础 sp；默认“大”为 1.2。最终显示仍交给 Android 的系统字体缩放处理。

| 角色 | 基准 | 字重 |
|---|---:|---|
| 页面主标题 | 32 sp | Semibold |
| 首页联系人称呼 | 26 sp | Semibold |
| 主要按钮 | 24 sp | Semibold |
| 表单与正文 | 22 sp | Normal / Medium |
| 辅助说明 | 18 sp | Normal |

档位固定为：标准 1.0、大 1.2、特大 1.4、超大 1.6。默认选中“大”。不要再增加单独的“首页字号”“姓名字号”“按钮字号”设置。

应用倍率先作用于基础 sp，再由系统解析 sp。不能覆盖 LocalDensity 的系统 fontScale 为 1，也不能把系统字号和应用倍率重复乘两次。Android 的字体放大可能为非线性；布局判断以实际测量结果为准。[Compose 可缩放内容说明](https://developer.android.com/develop/ui/compose/accessibility/scalable-content)

### 7.3 图形和触控

| 项目 | 标准档要求 |
|---|---|
| 常用主操作可视图形 | 40～48 dp，随档位适当增大 |
| 家属入口图形 | 至少 32 dp |
| 所有可点区域 | 至少 56 × 56 dp；主要按钮至少 64 dp 高 |
| 首页卡片 | 整张都可点击，不能只有底部听筒可点 |
| 触控目标间距 | 至少 12 dp；卡片间建议 16 dp |
| 卡片圆角 | 16 dp |
| 页面左右留白 | 16 dp；极窄窗口可降至 12 dp，不能挤压触控间距 |
| 输入框 | 至少 64 dp 高，随多行内容增高 |

Android 通用触控目标最低建议为 48 dp；本产品主动采用更大的默认目标。不要依靠透明区域重叠扩展点击面积。[Compose 无障碍默认规则](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)

图形不使用 sp，但应随应用档位从标准尺寸逐级增加，例如主操作 40、48、56、64 dp。触控区域不能因文字调小而低于上述最小值。

## 8. S01：亲人首页详细设计

### 8.1 页面结构

从上到下只有：

1. 简单标题“打电话”。
2. 与标题分区的“家属设置”入口，图形加文字，视觉优先级低于亲人卡。
3. 固定顺序的亲人卡片区域。

不显示电话号码、不显示通话次数、不展示新闻、天气、日期大时钟或每日提示。

标题与家属入口在同一行放不下时分成两行，禁止挤小标题或把家属入口移出屏幕。两行头部仍只表达标题和管理入口，不增加新的首页功能。

参考结构仅表达层级，不能按字符宽度直接实现像素布局：

~~~text
┌─────────────────────────────┐
│ 打电话          ⚙ 家属设置  │
│                             │
│ ┌──────────┐ ┌──────────┐    │
│ │ 亲人照片 │ │ 亲人照片 │    │
│ │   女儿   │ │   儿子   │    │
│ │ ☎ 拨打   │ │ ☎ 拨打   │    │
│ └──────────┘ └──────────┘    │
│ ┌──────────┐ ┌──────────┐    │
│ │ 亲人照片 │ │ 亲人照片 │    │
│ │   老伴   │ │   小孙女 │    │
│ │ ☎ 拨打   │ │ ☎ 拨打   │    │
│ └──────────┘ └──────────┘    │
└─────────────────────────────┘
~~~

图中 Unicode 符号是示意；正式资源应使用清楚的矢量图形，不能依赖各机型不同的 emoji 外观。

### 8.2 列数与照片

- 首页最多两列，只有纵向滚动，不横向翻页，不做轮播。
- 可用宽度小于 360 dp：单列。
- 可用宽度至少 360 dp：仅当每列足以容纳实际字号下的 4 个汉字及卡片左右内边距时使用两列；否则单列。
- 测量基于当前窗口、系统字号和应用字号，不只检测屏幕像素数。
- 两列卡片照片采用接近满宽的方形，扣除内边距后尽可能达到约 120 dp 或以上；小窗不足则单列。
- 单列照片建议至少 160 dp，图片和文字仍按清晰的纵向层级排列。
- 同一行卡片采用一致行高；较长名称撑高该行，不让相邻卡片参差到难以辨认。
- 名称可以超过两行；不得强制缩字。卡片高度为内容驱动，不以固定屏幕比例裁字。
- 宽屏仍不超过两列，可约束内容最大宽度居中；不突然变成四列密集通讯录。

### 8.3 点击和反馈

- 照片、称呼、绿色区域及卡片内空白都属于一个可访问的点击目标。
- 按下给予明显但短暂的压下反馈；支持轻微系统触觉反馈，设备不支持也能完成操作。
- 手指滑动成为滚动时不触发拨号；按下后拖出卡片并松开不拨号。
- 快速多次点击、两根手指同时点、连点不同亲人，只允许当前有效动作产生一次拨号请求。
- 不把长按设置成另一种危险动作。
- 系统电话界面启动前，可短暂显示“正在打开电话”；不能显示“已接通”。
- 从系统电话界面回来保留原来的浏览位置，不自动再拨、不弹评分窗口。

### 8.4 无照片

占位图为固定颜色背景加粗人物轮廓，不用姓名首字代替唯一识别线索。占位颜色随联系人存储，不随每次启动随机变化。家属管理页明显标记“还没有照片”，提醒真人照片更便于老人辨认。

占位色只能从固定六色中选择：LIGHT_BLUE、LIGHT_AMBER、LIGHT_PURPLE、LIGHT_TEAL、LIGHT_ROSE、LIGHT_GRAY。其具体背景值使用浅色且与深墨蓝轮廓形成对比；不能占用拨号绿色或取消红色的整块行动样式。

| 占位色枚举 | 背景值 |
|---|---|
| LIGHT_BLUE | #DBEAFE |
| LIGHT_AMBER | #FEF3C7 |
| LIGHT_PURPLE | #F3E8FF |
| LIGHT_TEAL | #CCFBF1 |
| LIGHT_ROSE | #FFE4E6 |
| LIGHT_GRAY | #E2E8F0 |

六色都使用 Ink 色人物轮廓。它们只是辅助区分，不能把同一个通用人物轮廓当成真人照片一样容易识别。

### 8.5 首页状态

| 状态 | 展示和行为 |
|---|---|
| 初次安装／无联系人 | 大人物图形 + “请家人添加亲人” + 大按钮“家属设置”；没有可误拨的示例联系人 |
| 正在读取 | 保留页面结构，显示简单加载标识；不能暂时显示假联系人 |
| 有联系人 | 直接可点，不先展示教学页 |
| 权限未开 | 仍显示联系人；点卡进入拨号帮助，不能悄悄改成另一套拨号操作 |
| 正在交给系统 | 所有卡片暂时防连点；不允许排队等待拨打其他人 |
| 数据读取失败 | 大图形 + “暂时读不到亲人信息” + 重试／请家人帮忙；不能显示空列表并建议重新添加 |

## 9. S02～S04：家属入口和管理

### 9.1 家属入口防误操作

点击“家属设置”先进入 S02，只提供两个大操作：“返回打电话”“进入设置”。说明一句：“这里可以修改亲人和字体。”

不做算术题、手势密码、PIN、指纹、长按 3 秒或连续点 5 次。这个入口是防误入，不是安全认证。任何进入本地应用的人仍可能查看联系人，不宣称家属区被加密保护。

### 9.2 家属设置菜单

按稳定顺序垂直排列：

1. 管理亲人。
2. 从手机通讯录导入。
3. 从文件导入。
4. 导出亲人。
5. 字体大小。
6. 拨号权限与使用说明。
7. 返回打电话。

每项采用大图形、标题及必要的一行说明，不使用无标签九宫格。说明“从手机通讯录导入”读取本机系统通讯录；“从文件导入”读取另一台手机导出的专用 ZIP，两者不能混叫“同步”。

### 9.3 管理列表

- 每行显示小照片、称呼、完整号码及明确编辑入口。
- 允许家属搜索姓名和号码；搜索不会影响首页排序。
- 添加按钮明确写“添加亲人”，不是单独一个加号。
- 排序使用“上移”“下移”按钮；首项／末项禁用对应动作。V1 不依赖拖拽。
- 删除入口放在编辑页底部危险区，与保存按钮隔开。
- 管理行本身不触发真实拨号。避免家属浏览或排序时误拨。

## 10. S05～S06：添加、编辑与照片

### 10.1 字段顺序

照片 → 称呼 → 电话号码 → 无照片时的占位色 → 保存。

- 照片按钮写“选择照片”或“更换照片”。V1 不内置拍照；可由家属先用系统相机拍照后选择。
- 称呼标签写“老人怎么称呼这个人”，示例说明可用“女儿”“老伴”“小明”。
- 名称最多 12 个 Unicode 码点；推荐 2～6 个字。超长报错，不自动截断。
- 电话输入框支持粘贴、开头加号和常见格式分隔符；具体校验遵循逻辑文档，不能只接受 11 位手机号码。
- 名字和号码必填，照片可暂缺。
- 同号时说明“已有亲人使用这个号码”，允许家属确认保存，照顾共用座机情形。
- 保存中禁用重复提交。成功后明确反馈并返回管理列表。
- 取消有未保存内容时询问“放弃这次修改？”；确认前数据库保持原样。

### 10.2 照片调整

- 显示方形裁切预览，让家属确保脸在中央且完整。
- 使用已验证的裁切组件；本项目不自行实现复杂图片编辑器。
- 有清楚的“使用照片”“取消”按钮。
- 只保留方形裁切和必要缩放／移动，不增加滤镜、美颜、贴纸、AI 生成脸。
- 当前图像解码不支持、过大或损坏时说明“这张照片无法使用，请换一张”，保留原照片。
- 预览图调整只影响草稿，点联系人保存后才永久写入。

## 11. S07：手机通讯录批量导入

- 首次主动进入时，先说明“读取手机通讯录，用来选择要添加的亲人”，再请求联系人权限。
- 拒绝权限显示重新授权入口与“手动添加”，不循环弹框。
- 列表有搜索、多选和选中数量；只展示姓名、号码、现有头像。
- 一个系统联系人有多个号码时，展开明确的号码单选。没有确定号码时不能直接导入。
- 确认页列出待添加、重复跳过、待修改、缺照片数量。
- 超长名字、无效号码必须由家属修改或取消选择；缺照片可以确认使用占位图。
- 目标机已有的号码默认跳过，保留当前称呼和照片。
- 导入前允许调整针对这位老人的称呼。
- 导入后显示实际新增和跳过数量，不显示没有依据的“同步完成”。

## 12. S08：文件导入

### 12.1 选择和预检

先打开系统文件选择器，选择 ZIP 后显示“正在检查文件”。检查结束前不出现可执行的“导入”按钮。文件不合法时停留在错误页，清楚说明没有修改当前联系人。

### 12.2 预览内容

- 文件名、导出日期、亲人总数、照片数。
- 按文件顺序显示照片、称呼、号码。
- 默认模式：“添加新亲人，保留当前亲人”。
- 次要选项：“用这个文件替换所有亲人”。
- 默认追加模式列出“将新增 N 位，保留现有 M 位，跳过 K 位”。
- 一句帮助：“不同老人对同一人的称呼可能不同，导入后可修改称呼。”
- 本机字号不会因导入改变；预览文字可说明这一点。

### 12.3 整体替换确认

只有选中替换模式才出现危险确认页，写明：

> 将删除本机现有 M 位亲人，改为文件中的 N 位。照片和排列顺序也会替换。

提供“先导出当前亲人”“取消”“确认替换”。红色实心按钮必须写“确认替换”，不能只写“确定”。不自动切换到替换模式，不把“全选”等同于“清空后恢复”。

### 12.4 进行中与结果

预检阶段可以取消。正式事务提交期间短暂显示“正在保存，请稍候”，防止重复操作。结束后准确显示新增／跳过或替换数量。进程中断后重新进入以数据库实际内容为准，不凭缓存显示“成功”。

## 13. S09：文件导出

- V1 导出全部 App 内联系人，包含姓名、号码、照片和排列顺序。
- 页面写明“会导出 N 位亲人和 P 张照片”，照片不能隐性丢失。
- 不导出系统通讯录里尚未选入本应用的人，不导出本机字体大小和权限。
- 一句隐私说明：“文件里有亲人的姓名、电话和照片，请只发给信任的人。”
- 生成完成后提供“保存文件”和“分享文件”两个明确动作。
- 分享调用系统分享面板；不在本应用里登录聊天账号，不自动选择接收人。
- 保存成功与分享面板打开分开描述。“已打开分享”不能写成“对方已收到”。
- 取消系统保存／分享不能显示导出失败或修改联系人。
- 文件为 ZIP，家属把整份文件传到另一台手机，不需要手动解压后逐个导入照片。

## 14. S10：字号设置

用四个可点击的大选项卡／单选项：“标准”“大”“特大”“超大”，每项展示真实大小。不要使用只能精细拖动的滑块。

下方放真实的亲人卡片预览和正文／按钮预览，不放仅一个“A”。预览使用本地示意图，不绑定真实拨号动作。切换档位立即更新预览；“保存”后全局生效，“取消”恢复原档位。

字体设置页也使用当前预览字号，因此必须可滚动；任何档位下保存与取消均可到达。不得因字号变大导致无法调回较小档。字体只作用于本应用，不能宣称放大系统电话、桌面或系统权限弹窗。

## 15. S11：权限、错误与反馈文案

老人看到的文案要短，细节给家属页。不得显示堆栈、异常类名或内部状态码。

| 情况 | 老人看到的内容 | 可执行动作 |
|---|---|---|
| 没有拨号权限 | “还不能打电话，请家人帮忙开启” | 家属设置／返回 |
| 重新开启权限后 | “已开启，再点亲人照片打电话” | 返回首页；不自动拨打 |
| 没有可用电话程序 | “这台设备暂时不能打电话” | 返回／家属帮助 |
| 系统拒绝启动电话 | “电话没有打开，请再试一次” | 返回首页后重新点击 |
| 联系人已删除／无效 | “这个亲人的信息有问题” | 家属设置／返回 |
| 无 SIM、无服务等 | 系统电话页面提示 | 不伪造本应用的检测和修复按钮 |
| 文件损坏 | “文件无法导入，当前亲人没有改变” | 重新选择／取消 |
| 保存空间不足 | “空间不足，没有保存这次修改” | 返回；保留原联系人 |

可恢复错误必须保持在页面上，直到用户处理；不能只闪一个短 Toast。简短成功反馈可以使用 Snackbar，但不能遮住主按钮。

## 16. 无障碍、系统行为与适配

- 使用清楚的语义标签，如“给女儿打电话”；卡片整体一个点击节点。
- 装饰性照片／图形不重复朗读同样内容，避免“女儿、图片女儿、拨打女儿”连续三次。
- TalkBack 的系统激活方式可能是双击；不要覆盖它，也不要据此在普通触控流程增加双击要求。
- 焦点按视觉顺序：标题、家属入口、逐行亲人卡；不跳到不可见区域。
- 焦点框清楚可见；按钮不能只通过透明度表达禁用。
- 错误应被辅助技术发现，必要时使用适度的 live region；不不断打断朗读。
- 遵守状态栏、导航栏、刘海和键盘边距；输入框不能被键盘遮住。
- 系统返回遵循当前页面：返回上一级；有未保存修改才确认。不能拦截所有返回或把老人困在应用中。
- 默认竖屏设计，同时支持横屏／窄窗口重排；不靠锁定屏幕方向掩盖布局问题。
- 页面允许因大字号而滚动，但不需要二维滚动。
- 动画短、少；尊重系统减少动画设置；加载时不使用闪烁和强烈明暗交替。
- 系统深色模式下应用保持本方案的浅色内容，需正确配置系统栏图标明暗，保证可读。

1. 完整页面树，标出 S01～S11 与系统页面 X01～X03。
2. 颜色、文字、间距、图形、按钮与卡片组件变量表。

4. 320 dp 窄屏、360 dp 常见屏、较宽屏、横屏的布局。
5. 系统字体 1.0、1.3、2.0 × 应用档位的代表组合，特别展示单列重排与长姓名。
6. 图标全套资源和遮罩／灰度预览。
7. 首页、添加、导入预览、字号、权限帮助的逐步交互说明。
8. 与功能验收编号相对应的设计自查表。

## 18. UI 验收硬性检查

- [ ] 看到照片后，普通触控一次即可请求拨号，没有中间确认页。
- [ ] 照片、姓名和绿色区域点击结果一致，管理区没有误拨热点。
- [ ] 首页没有添加、删除、导入等次要操作混入亲人卡片。
- [ ] 名字完整、图形足够大、卡片间距足够，不靠省略号和缩字过关。
- [ ] 标准档也保持可读，超大档可完整访问所有操作。
- [ ] 灰度下仍能辨认拨打、取消、删除和返回。
- [ ] 桌面图标具备固定粗听筒轮廓，未宣称可以强制覆盖系统主题。
- [ ] 替换导入有准确数量与明确危险动作文字。
- [ ] 电话交给系统后没有虚构的 App 内挂断控制。
- [ ] 设计使用真实可实现的数据状态，没有假通话成功、假分享送达和假联系人。

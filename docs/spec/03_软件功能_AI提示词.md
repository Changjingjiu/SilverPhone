## 1. 给执行 AI 的任务

你是一名负责需求落地和验收的 Android 产品工程师。请按照本文和配套文档实现完整 V1。

**产品一句话：让不识字、看不清小字、不熟悉手机的老人，认出亲人的照片后点一下就能发起普通电话；家属配置一次后，可把照片电话本完整复制给另一位老人。**

本项目的价值是操作简单、认得出、打得对、资料能完整复制，不是功能数量。不得擅自把它扩展成养老平台、全功能通讯录、社交软件、默认电话系统或老人桌面。

## 2. 用户和典型场景

### 2.1 日常用户：老人

可能同时存在以下情况：不识字或识字少、看不清小字体、手指点击不够精准、不理解菜单、容易忘记复杂步骤、设备较旧。

不能假定所有老人都有认知障碍、完全不会用手机，或必须使用同一种字号。提供简单可学的默认流程，同时保留由家属调整字号和顺序的能力。

### 2.2 配置用户：年轻家属

负责添加照片、确认号码、设置适合的称呼、调整顺序、开启系统权限、跨手机传文件以及教一次日常操作。

家属的配置步骤可以比老人拨号流程稍多，但必须批量操作、明确反馈，不能复制 30 位亲人还得逐张重新选头像。

### 2.3 关键场景

| 场景 | 用户期望 | 必须交付的结果 |
|---|---|---|
| 第一次给老人配置 | 添加几位常联系的亲人 | 照片、称呼和号码永久保存，退出重启仍在 |
| 老人给女儿打电话 | 看到女儿照片，点一下 | 只发起一次该号码的系统拨号请求 |
| 老人不认识字 | 靠熟悉的脸、轮廓、位置辨认 | 不要求先搜索姓名或阅读菜单 |
| 原手机已有通讯录 | 家属批量选择亲人 | 不必逐个手抄号码，选定一人一个号码 |
| 给另一位老人配置 | 将已有配置导出传过去 | 一份文件包含照片、称呼、号码、顺序 |
| 两位老人称呼不同 | 一边叫女儿，一边叫姐姐 | 默认导入不覆盖目标机已有称呼 |
| 视力变差 | 把全应用文字调大 | 自动重排，操作仍完整可达 |
| 换旧手机或离线 | 能正常打开和查找亲人 | 不依赖登录、服务器或 Google Play 服务 |
| 点错联系人 | 使用系统电话页取消／挂断 | 不给老人一个无效的 App 内取消按钮 |

## 4. 功能逐项规格

### F01：桌面识别

App 图标使用荧光黄绿色底和深墨蓝大听筒，名称“SilverPhone”。图标资源必须覆盖最低系统与现代自适应图标要求，不能使用 Android 默认机器人图标交付。

家属说明写清：把应用放在固定桌面位置；系统允许时放大桌面图标；若主题把所有图标改成相同颜色，可以选择关闭主题图标。

颜色是否比同一台手机上的其他 App 更容易辨认，需要目标机实际比较。不能承诺“全市场唯一颜色”，不能保证系统主题永远不改色。

### F02：老人亲人首页

- 直接显示亲人照片、称呼、绿色拨打标识。
- 一列或两列，最多两列，只纵向滚动。
- 首页不显示号码、编辑按钮、删除按钮、广告或管理搜索。
- 典型 4～12 位亲人时，优先展示清楚的大脸；500 条时也不能把卡片缩成小图标。
- 顺序固定，重启、拨号返回和编辑照片不能自动改序。
- 没有资料时只显示家属配置入口，不生成假亲人。

### F03：点照片拨号

正常前提下，一次普通点击整张卡片，直接使用 ACTION_CALL 请求系统发起该卡片唯一绑定号码的电话。

不新增确认、不要求长按、不展示联系人详情、不先弹号码选择。快速连点只产生一次请求。授权回来不自动继续拨打，需新点击。

电话接通、取消呼叫、挂断、免提、蓝牙和通话中键盘都属于系统电话界面。不能把“打开系统拨号盘待用户再次点拨号”标为本功能已完整满足。Android 对拨号 Intent 的定义见：[官方说明](https://developer.android.com/guide/components/intents-common#Phone)。

### F04：家属设置

首页点“家属设置”，再点“进入设置”。不引入账号、密码或隐藏手势。

设置菜单必须包含管理亲人、手机通讯录导入、文件导入、文件导出、字体、拨号权限说明与返回首页。每个入口有明确图形和文字。

### F05：亲人增删改

必填姓名和号码；照片允许暂缺。姓名最多 12 个 Unicode 码点，一张卡一个号码。号码兼容正常国际前缀、座机和短号码的语法范围，不限于 11 位手机号。

同号和同名可以存在，但提醒家属用照片及称呼区分。编辑保留 ID 和位置；新建追加末尾；删除确认后清理对应照片并调整顺序。

所有保存只有落库成功才显示成功。取消、格式错误或空间不足都保留原数据。

### F06：照片

使用系统选图入口，提供方形预览和必要裁切调整。照片保存后必须成为 App 私有数据，不受相册原文件删除、重命名或授权失效影响。

规范化结果为不超过 512 px 方形 JPEG、单张不超过 128 KiB；移除原图元数据。所有照片随导出文件传递。具体边界执行逻辑文档，不自行扩大原图存储规模。

V1 不内置拍照、美颜、滤镜、动态头像和 AI 生成亲人照片。家属可以先使用系统相机，再到本应用选择照片。

### F07：排序和搜索

排序仅家属可改，提供上移／下移，不依赖拖动手势。管理页支持按名字或号码搜索，搜索结果不改变首页排序。

不按通话次数自动换位，不增设收藏分组、多个家庭空间和复杂标签系统。

### F08：手机通讯录导入

家属主动授权后，多选系统通讯录中的亲人。只读取必要字段，不修改系统联系人。多个号码必须明确选择一个，避免老人点卡后再选。

导入前显示照片、称呼、号码及待处理问题；名字不适合当前老人时可调整。已有号码默认跳过；缺照片可以明确使用占位图；无效号码不得静默导入。

这是一次性复制，不是后台双向同步。以后系统通讯录变化不会自动改动亲人卡。

### F09：完整导出

一份 ZIP 内必须包含 App 内全部亲人的照片、姓名、号码、占位色和排列顺序。空联系人列表不能导出用来清空另一台设备的包。

文件不含未选入应用的系统通讯录、不含权限、SIM 选择与字体偏好。字体是当前老人的本机设置，不应随着另一位老人的联系人一起覆盖。

不得只导出 JSON、CSV 或本机照片路径。不得让家属另外打包相册。

### F10：保存和分享

完整生成后，家属可使用系统保存文件界面或系统分享面板。接收人、传输工具和保存位置由家属选择。

应用不能在后台自动发文件，不能假定一定安装微信，不绑定某个云盘。发送工具若有文件大小限制，由其反馈；App 不能把整个系统分享过程称为已确认送达。

导出文件未加密，操作页提供简短隐私提示。只给可信家属共享，不上传到应用服务器。

### F11：文件导入

- 先选择文件、完整校验，再预览，最后确认写库。
- 默认追加：同 ID 优先匹配，其次按规范化号码匹配；匹配项保留目标机原资料。
- 文件内部不同人共用号码的情况按逻辑文档处理，不能在空目标机静默丢掉其中一人。
- 整体替换必须主动选择并再次确认影响数量，提供先导出当前资料入口。
- 文件有坏照片、无效号码、未知协议、越界路径或超限，整体拒绝且本机不变。
- 整次写入失败回滚，不能部分新增再让家属自己补齐。
- 同一包反复追加不不断产生重复卡。

### F12：字号

标准 1.0、大 1.2、特大 1.4、超大 1.6，默认大。调整覆盖所有应用内页面。系统字体放大仍被尊重；不能禁用无障碍缩放。

设置页有真实预览，保存全局生效，取消恢复原值。空间不够改为一列或纵向滚动，不靠自动缩字、压小按钮和隐藏操作。

照片和图形也应保持足够大；本功能不能控制系统电话页面、桌面图标或系统弹窗字号。

### F13：权限与反馈

只在需要时请求 CALL_PHONE 和 READ_CONTACTS。选图及文件读写使用系统授予的 URI，不申请全文件权限。

必须有首次空态、加载、权限拒绝、无电话处理程序、图像失败、导入预检失败、容量不足、保存失败、用户取消和操作完成状态。

数据错误不能显示成空联系人；打开电话 Intent 不能显示成已接通；打开分享面板不能显示成对方已收到。

### F14：本地数据与隐私

不注册、不登录、不联网、不接广告和统计 SDK。联系人与照片保存在 Room；缓存限期清理。导出只在家属操作后生成；不记录完整电话和照片到日志。

系统备份和传输需要显式配置排除规则，不能因为“代码没有服务器”就宣称所有系统行为绝对不涉及云端。

### F15：兼容和无障碍

最低 Android 6.0 / API 23，默认覆盖该版本至实施时已发布稳定的 Android。不得将“在新手机能运行”当成低版本测试完成。

不依赖 Google Play 服务、在线字体或远程图标。检查 32 位旧设备的依赖和 APK 安装条件；若存在原生库，必须检查实际 ABI 及现代系统页大小要求。

适配小屏、大系统字号、横屏、屏幕阅读器、色觉差异和系统返回。关键卡片具备合适语义；不只依赖颜色区别拨打与取消。

### F16：家属交接说明

设置内提供简短说明，工程 README 提供完整说明。家属需要知道怎么设置默认语音 SIM、把图标固定到桌面、调整字号、教老人看照片点一下以及在系统电话页取消／挂断。

不能把完成操作的前提藏在开发文档里，例如明明需要电话权限却没有应用内提示。

## 5. 明确不属于 V1 的内容

以下功能即使看起来与老人有关，也不要自行实现、预留复杂框架或放置“敬请期待”入口：

- 用户账号、家属账号体系、云端数据库、实时云同步、远程代管。
- 微信拨号、视频通话、聊天、短信、群聊、朋友圈。
- 定位、电子围栏、跌倒检测、健康监测、吃药提醒、SOS 联动。
- AI 语音助手、云语音识别、语音克隆、录音、语音导航。
- 取代默认电话 App、通话录音、自定义通话中页面、悬浮挂断按钮。
- 取代桌面、锁屏接管、无障碍服务自动操作其他应用。
- 广告、付费会员、积分、推送、使用排行榜。
- 自动推荐联系人、根据通话次数排序、复杂亲属树。
- 一人多号码现场选择、分机拨号串、USSD/MMI、SIP。
- 任意 CSV／Excel／vCard 导入和历史备份格式转换。
- 历史数据库升级迁移、多个旧界面保留、兼容开关。
- 动态换肤、深色主题开关、可编辑品牌配色和多语言切换。
- 自动下载更新、应用商店发布、后台安装或对外上传构建。

未来有新需求应作为新的明确任务处理。现在不要“顺便”把它们塞进 V1。

## 6. 五条完整用户旅程

### 6.1 家属首次配置

1. 安装并打开 App，看到无联系人状态。
2. 两步进入家属设置。
3. 选择手工添加，或授权后从系统通讯录批量导入。
4. 为常用亲人添加清楚的真人照片和老人熟悉的称呼。
5. 调整排序与字体大小，预览首页。
6. 在家属设置中授予直接拨号权限；必要时去系统设置默认语音 SIM。
7. 用明确允许的测试号码验证一次实际拨号和返回，再把桌面图标固定好。
8. 教老人：“找到这个亮色电话图标，打开，看照片，点要找的人。”

测试号码必须由测试人员指定并获得接听者同意，不自动拨打导入联系人或紧急号码。

### 6.2 老人日常拨号

打开 App → 看照片／必要时往下滑 → 点亲人卡一次 → 系统电话处理 → 通话后返回原列表。

这一旅程不能穿过家属设置、文件页面和重复权限说明。若权限被系统撤销，明确引导家属帮助，不能悄悄更换交互。

### 6.3 把第一位老人的资料给第二位老人

A 手机进入家属设置 → 导出亲人 → 保存或分享整份 ZIP → 通过家属选择的工具传给 B 手机 → B 手机打开 App → 家属设置 → 从文件导入 → 查看照片与称呼 → 默认追加 → 确认 → 检查数量和照片 → 调整第二位老人的称呼／字号。

不必登录同一账号，不必手动解压，不必逐张重新选择照片。此后两台手机各自独立保存，后续修改不自动同步。

### 6.4 重复传入同一文件

再次选择同一文件 → 预览显示已有条目将被跳过 → 确认后新增 0 → 已有顺序、称呼、照片和字号保持。

### 6.5 替换全部联系人

先完成正常文件校验 → 主动选择全部替换 → 显示旧／新数量 → 可先导出旧资料 → 再确认替换 → 原子提交 → 展示新列表。中途失败时仍看到完整旧列表。

### 7.2 设备与视觉矩阵

最低覆盖：

- API 23：低版本基线。
- API 28：较旧且常见的 Android 文件和权限行为。
- API 30：现代存储及权限相关行为。
- API 33：主题图标和现代系统行为。
- API 35／36：新系统边距、字体及目标 SDK 行为；实施时还应加入已发布的最新稳定 Android。
- 宽度 320、360 和较宽窗口；竖屏与横屏。
- 系统字体 1.0、1.3、2.0，结合应用标准／默认大／超大档。

无需对所有维度做完全笛卡尔积，但必须覆盖最旧系统、最小窗口、最大字体、不同电话／文件处理程序等关键组合。模拟器可证明布局和系统 API 路径；至少一台有通话能力的目标真机才能验证真实拨出、双卡和返回行为。

### 7.3 目标老人可用性验证

建议由家属陪同至少 3 位目标用户试用，优先包含识字少和需要大字的人。这里是拟定的验证方案，不代表已经招募或测试。

只演示一次，然后观察能否：从桌面找到图标、找到指定亲人、点正确照片、知道电话已进入系统界面。记录是否需要提示、是否误触和哪一步停住。首次练习使用不会产生真实呼叫的测试构建；真实拨号单独安排并告知相关人员。

桌面颜色、卡片大小和顺序是否易记，要依据观察调整，不凭设计者感觉宣称“适合所有老人”。调整必须保留本套功能边界。

## 8. 性能与资源目标

以下为实现和测量目标，不是当前已通过指标：

- 2 GB 内存的目标旧手机，常用 12～24 位联系人时，冷启动到首页可操作目标不超过 3 秒。
- 点卡后的本应用视觉反馈目标在 100 ms 内；系统电话启动和网络接通时间单独记录，不计成应用自有能力。
- 首屏加载不等全部 500 张照片解码；只加载可见及少量邻近项。
- 500 条完整照片导入／导出采用有界流式处理，显示真实阶段或计数，不长时间无反馈。
- 不因大图、恶意 ZIP 或边界数据导致 OOM／ANR；不启用 largeHeap 掩盖问题。
- 不设置后台常驻服务，不为本地通讯录交换长期唤醒手机。

如果旧机达不到目标，报告机型、数据量、耗时及改进结果。不能把未测目标改写成已实现能力。

## 1. 给执行 AI 的角色与任务

你是负责落地的原生 Android 工程师。请完整执行四份文档，用 Kotlin、Jetpack Compose、Room 实现可安装的本地照片拨号应用。

不要替换技术栈，不做 WebView 页面，不引入服务器，不先搭建大而空的框架。先跑通能持久保存一位亲人照片并单击拨号的应用，再逐层增加已约定功能。

当前文档是工程约束，**尚没有实际工程构建或设备验证结果**。文档中核对过的官方版本与平台规则，不等于整组依赖已经在一起构建通过；你必须执行 P0 并记录实际结果。

## 3. Android 版本与工具链

### 3.1 最低系统是明确的产品合同

- minSdk 固定为 23，即 Android 6.0。
- 用户只说“低版本”，未指定 5.x；API 23 是本套文档明确标注的默认决定。
- 当前 AndroidX 默认 minSdk 为 23，Room 2.8 系列也以 API 23 为最低版本。不能声称“最新版 Compose 和 Room 随便配 minSdk 21 就能用”。[AndroidX](https://developer.android.com/jetpack/androidx/versions)、[Room 发布记录](https://developer.android.com/jetpack/androidx/releases/room)
- 不使用 tools:overrideLibrary、禁用 minSdk 检查或删除 lint 来强行宣称兼容。
- 支持 API 23 所需的官方资源分级和公共 API 适配，是当前功能本身。不得误解“删除历史兼容层”为删除旧手机支持。
- 用户若明确要求 Android 5.x，需要重新制定依赖路线和验收范围；当前版本不偷偷增加另一套旧依赖分支。

### 3.2 compileSdk 与 targetSdk

compileSdk、targetSdk 选实施时已发布的稳定 Android SDK，并记录为实际整数；不得使用预览 SDK。两者与 minSdk 是不同概念，不能为了“支持旧手机”一起降到 23。

以能支持所选稳定 SDK 和所有依赖元数据要求的 AGP / Gradle 组合为准。若随后要发布到应用商店，再核对发布时的目标 API 要求；本任务不自动包含商店发布。

### 3.3 开工时必须完成的版本锁定

以下是截至 2026-09-17 官方页面的核对点，而非伪造的整组构建结果：

| 组件 | 核对点 | 实施规则 |
|---|---|---|
| Room | 官方发布页列出 2.8.5 | 优先从 2.8.5 开始核对，runtime/compiler/plugin 同一版本 |
| Compose | 官方稳定 BOM 示例为 2026.08.00 | 使用稳定 BOM 统一 UI 库，禁止 alpha/beta BOM |
| Kotlin / Compose 编译插件 | 官方示例使用 Kotlin 2.x，同版本 compose compiler plugin | Kotlin 与 org.jetbrains.kotlin.plugin.compose 精确一致 |
| Activity / Lifecycle | 不属于 Compose BOM 统一范围 | 单独锁定兼容的稳定版本，不能以为 BOM 自动管所有 AndroidX |
| KSP | 使用官方支持的 KSP2 路线 | 单独核对 Kotlin／Room 支持，不凭旧的版本号拼接规则猜测 |

执行顺序必须是：

1. 查询 Google Maven／官方发布页，选稳定组合，记录选定日期。
2. 检查所有直接和传递依赖的 minSdk、minCompileSdk、Kotlin 元数据与 AGP 要求。
3. 写入 libs.versions.toml，固定版本；不写 +、latest.release 或动态范围。
4. 在 P0 构建空骨架、创建 Room 表、装到 API 23 并打开。
5. 将实际 AGP、Gradle、JDK、Kotlin、KSP、BOM、Room、Coil、Cropper 版本和结果写入 build-matrix.md。
6. 如需修正版本，只调整满足既定平台和功能的稳定组合；不得抬高 minSdk 或替换技术栈来绕过问题。
7. P0 通过后后续阶段不无故升级依赖；有明确问题才改，改后复验相关矩阵。

官方入口：[Compose BOM](https://developer.android.com/develop/ui/compose/bom)、[Compose 编译插件](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler)、[Kotlin 与 Android 构建支持](https://developer.android.com/build/kotlin-support)、[KSP](https://kotlinlang.org/docs/ksp-quickstart.html)、[AGP 兼容表示例](https://developer.android.com/build/releases/agp-8-13-0-release-notes)。

## 5. 数据流与职责

~~~text
Compose 页面
   │ 用户事件
   ▼
ViewModel / StateFlow
   ├── 纯 Kotlin 校验与 ImportPlanner
   ├── ContactRepository ── Room
   └── 一次性前台效果 ── PhoneLauncher / 系统选择器

BackupReader / PhotoNormalizer
   └── 私有暂存、完整预检 ── ImportPlan ── Repository 事务提交
~~~

- 页面只负责展示状态和传递事件，不直接查数据库、解 ZIP 或拼电话 URI。
- ViewModel 负责当前页面状态与操作协调，不持有 Activity 长引用。
- 仓储负责统一写操作、顺序、集合修订号、事务和 Flow。
- 号码校验、重复计划、协议规则尽可能为纯 Kotlin，可直接单测。
- Android 权限、ContentResolver、文件选择器、Intent 保持在系统边界。
- IO／压缩／图片处理不在主线程执行；计算密集的图片编码合理调度，避免大量并行解码。
- 所有操作都返回明确成功／错误结果，不能用 null 同时表达取消、损坏和空集合。

## 6. Room 数据模型

### 6.1 采用三张表

**contacts**

| 列 | SQLite／Kotlin | 约束 |
|---|---|---|
| id | TEXT / String | 主键，规范 UUID |
| displayName | TEXT / String | 非空，业务层校验长度 |
| phoneNumber | TEXT / String | 已规范化，普通索引，非唯一 |
| sortOrder | INTEGER / Int | 非负，普通索引，仓储维护连续性 |
| placeholderColor | TEXT / String | 固定枚举字符串 |

**contact_photos**

| 列 | SQLite／Kotlin | 约束 |
|---|---|---|
| contactId | TEXT / String | 主键，外键指向 contacts.id，ON DELETE CASCADE |
| jpegBytes | BLOB / ByteArray | 不超过 128 KiB |
| sha256 | TEXT / String | 最终存储字节的摘要 |
| width | INTEGER / Int | 与 height 相等，1～512 |
| height | INTEGER / Int | 与 width 相等，1～512 |

**app_settings**

| 列 | SQLite／Kotlin | 约束 |
|---|---|---|
| id | INTEGER / Int | 固定为 1，仅一行 |
| fontPreset | TEXT / String | 默认 LARGE |
| contactsRevision | INTEGER / Long | 默认 0，联系人事务成功后递增 |

照片 MIME 固定为 JPEG，不必再为每一行保存相同字符串。联系人是否有照片可从关联表判断，不另外维护易失真的 hasPhoto 标志。

### 6.2 查询要求

- 首页查询只返回 id、displayName、phoneNumber、sortOrder、placeholderColor 和可空 photoSha256；不带 jpegBytes。
- 按 sortOrder ASC 查询；集合修订号和元数据的快照读取使用事务。
- 显示可见照片时按 contactId 单条异步读取，使用哈希缓存键。
- 不在 SELECT * 的联系人关系对象中一次取出 500 个照片 BLOB。
- Blob 使用 ByteArray，注意数组默认相等性行为；不要把巨大的字节数组当 Compose 稳定状态反复比较。
- 读写使用 suspend 和 Flow，不调用 allowMainThreadQueries。[Room 异步访问](https://developer.android.com/training/data-storage/room/async-queries)

### 6.3 事务要求

以下每种操作均应在同一 withTransaction 内完成：

- 新增或编辑联系人及其照片，并增加 contactsRevision。
- 删除联系人、级联删除照片、压紧顺序、增加修订号。
- 相邻顺序交换及增加修订号。
- 追加导入的全部新增行和照片，以及一次修订号增加。
- 全部替换的删除、写入完整新集合和增加修订号。

AppContainer 创建一个数据库实例与一个仓储写操作 Mutex；不要每个 ViewModel 单独创建数据库。导入和普通编辑使用同一写入口。批量导入从已验证的私有暂存资源逐张读入，不在事务里等待外部提供者。

### 6.4 数据库版本与历史路径

- 首版数据库 version = 1，exportSchema = true，提交生成的 schema。
- 不实现历史表结构、不生成“将来可能需要”的 Migration、不保留两套数据层。
- 不使用 fallbackToDestructiveMigration 或启动失败自动删库。
- 当前同一 schema 的版本更新必须保留数据；若未来明确要改 schema，另行定义数据处置需求，不能在本任务中暗自允许清空老人联系人。

“不做历史迁移”是范围约束，不是损坏或丢失用户数据的理由。

## 7. 设置为何也放 Room

本应用只有一个简单的字号偏好和联系人修订号。统一放在 Room 可以减少持久化机制并让修订号随联系人事务更新。

V1 不另加 DataStore、SharedPreferences、JSON 配置文件、远程配置或设置服务。动态权限不属于持久化偏好，必须每次按系统当前状态检查。

字体预览存在 ViewModel 草稿中；保存才写 app_settings.fontPreset。取消丢弃草稿，不能一边预览一边永久写库后再假装取消。

## 8. Compose 实现约束

- Single Activity + Navigation Compose；导航参数只传联系人 ID／操作 ID。
- ViewModel 提供不可变 UiState，页面使用 collectAsStateWithLifecycle。
- 首页使用 LazyColumn／LazyVerticalGrid，stable key 为联系人 UUID。
- 列数根据可用宽度与实际文字测量决定，最多两列。
- 名称和按钮不设会截断关键内容的固定高度，允许换行和纵向滚动。
- 字号由统一 Typography 工厂按档位生成 sp；保留系统 fontScale，不改成 1。
- 接入安全边距和 IME；新版目标 SDK 下不能遗漏 edge-to-edge 的布局影响。
- 点击卡片使用标准 clickable 语义，不通过自写原始触摸判断重做点击／滑动识别。
- 整张卡是一个语义节点；装饰图形不重复可访问标签。
- 拨号单次事件只能由前台宿主消费，不在 Composable 体内或可重复触发的状态收集器里直接执行。
- 裁切页 AndroidView 的生命周期、图片任务取消和资源释放必须处理。
- 不把业务对象／照片 Bitmap 存入导航回栈或 Bundle。
- 不用 Activity 重启来实现字号切换；状态更新即可。
- 品牌与行动色固定，明确关闭 Material 动态取色；V1 保持约定浅色主题。

## 9. 图片方案

### 9.1 加载

使用 Coil 3 的本地图片能力，共享一个 ImageLoader。只加载当前可见照片和少量预取，指定实际目标尺寸；按 contactId + sha256 更新缓存。

不要引入 coil-network-okhttp、Retrofit 或远程头像 API。官方示例包含网络模块是为了展示网络图；本项目不需要照抄这一依赖。[Coil 模块说明](https://coil-kt.github.io/coil/getting_started/)

内存缓存按低内存目标设备配置并测量，可从最多 8 MiB 且不超过可用堆约 10% 的保守上限起步；不创建自写无限 Bitmap Map，也不将所有原图常驻内存。[Coil ImageLoader](https://coil-kt.github.io/coil/image_loaders/)

如果使用 Room BLOB，自定义一个很小的 ContactPhoto 数据入口／Fetcher 将 ID 映射到 DAO 读取即可；这是连接现有数据源，不是重写图片解码和缓存库。先检查所选版本是否可直接处理 ByteArray，再选择最少代码的接入方式。

### 9.2 裁切和规范化

采用 com.vanniktech:android-image-cropper，优先其官方仍支持的 CropImageView 接入方式。项目 README 已将直接调用旧 CropImageActivity／部分一键 Contract 路径标为弃用，不在新项目里选弃用路线。[项目文档](https://github.com/CanHub/Android-Image-Cropper)

Compose 的 S06 页面负责自己的大按钮与文案，AndroidView 只承载裁切区域。系统选图由应用自己负责；禁用裁切库内置相机来源，不因此申请 CAMERA。

复用库的采样、矩阵和裁切能力；输出之后统一执行逻辑文档的 JPEG 尺寸、字节数和元数据处理。系统通讯录照片也走同一 PhotoNormalizer，不能绕过限制。

新选照片以私有缓存暂存。联系人保存后只有 Room BLOB 是长期来源；外部 URI 和裁切临时路径不得保存在 ContactEntity。

## 10. 电话与权限实现

### 10.1 Manifest 最小权限

必须依据实际实现核对最终合并 Manifest，而不是只看手写文件：

| 权限 | 是否需要 | 用途 |
|---|---|---|
| CALL_PHONE | 是，运行时申请 | 老人点卡直接请求拨号 |
| READ_CONTACTS | 是，按功能运行时申请 | 家属批量选入系统联系人 |
| INTERNET | 否 | V1 没有联网需求 |
| WRITE_CONTACTS | 否 | 不改系统通讯录 |
| READ_CALL_LOG／WRITE_CALL_LOG | 否 | 不读取或记录系统通话 |
| READ_PHONE_STATE | 否 | 不自行检测 SIM／通话状态 |
| CAMERA | 否 | V1 通过系统文件选择已有照片 |
| READ_MEDIA_IMAGES／READ_EXTERNAL_STORAGE | 否 | 使用选定 URI 的读取授权 |
| WRITE_EXTERNAL_STORAGE／MANAGE_EXTERNAL_STORAGE | 否 | 文件由 SAF 创建或打开 |
| POST_NOTIFICATIONS | 否 | 没有通知功能 |
| SYSTEM_ALERT_WINDOW／无障碍服务 | 否 | 不覆盖或操纵系统电话页 |

若依赖的 Manifest 引入不需要的权限，使用可解释的 manifest merge 规则移除，并确认相关功能确实未使用。

### 10.2 拨号入口

PhoneLauncher 只接受经过校验的 PhoneNumber 值。使用 ACTION_CALL 和 Uri.fromParts 构造 tel URI；当前前台 Activity 发起，不在后台 Service 中拨打。

如果先调用 resolveActivity／queryIntentActivities，需要按照当前 targetSdk 的包可见性规则声明必要 queries；也可以直接启动并捕获明确异常，避免为了“检测”申请 QUERY_ALL_PACKAGES。

使用 ContextCompat.checkSelfPermission 和 ActivityResultContracts.RequestPermission 管理权限。请求、拒绝、设置返回分别更新状态。不得用持久化的 hasPermission 布尔值替代检查。

本应用不是默认拨号器，不引入 RoleManager 申请电话角色，不实现 InCallService，不接通话控制 Telecom 框架。系统紧急号码行为不可绕过。[系统拨号角色与边界](https://developer.android.com/develop/connectivity/telecom/dialer-app)

## 11. 系统通讯录实现

- 使用 ContactsContract 和 ContentResolver，读取最少投影字段：联系人 ID、显示名、号码、号码类型、主号码标识、照片 URI。
- 只在授权且家属触发时查询；大系统通讯录后台读取，Cursor 用 use 关闭。
- 按系统联系人聚合多个号码，家属明确决定目标号码；不要把任意第一行当成主号码。
- 系统 lookup key／row ID 只用于当前选择过程，不作为 App 可移植 UUID。
- 空 Cursor、权限撤销、照片无法访问和部分记录格式差异转换为预览状态。
- 查询结果是选择源，只有确认后才复制进 Room；不为系统联系人建立后台观察同步服务。

## 12. SAF 与 FileProvider

### 12.1 同一条主文件路径

目标最低 API 已支持 Storage Access Framework。统一采用：

- 选择原始照片：OpenDocument，image/*。
- 选择导入文件：OpenDocument；允许选取 MIME 不准确的文件，最终以 ZIP 内容预检为准。
- 保存导出：CreateDocument，application/zip。

文件 URI 来自系统选择器，不推测 /sdcard/Download 等硬编码路径。只读／写授权范围内的文件；取消返回是正常结果。立即复制所需照片和导入文件到有界私有缓存，因此不需要永久保留原始 URI 作为联系人依赖。[官方 SAF 文档](https://developer.android.com/training/data-storage/shared/documents-files)

### 12.2 分享范围

FileProvider 设置 exported=false、grantUriPermissions=true，路径只暴露缓存下专用 exports/ 目录。不得暴露整个 cache 根目录、files 根目录或数据库。

分享使用 ACTION_SEND + content URI + MIME + FLAG_GRANT_READ_URI_PERMISSION，并配置所选 Android 版本所需的 ClipData。让系统分享面板选择接收程序，不使用 file:// URI，也不自动发送给任何人。

导入暂存与编辑草稿放在 exports/ 以外的私有目录，不能通过共享 Provider 访问。

### 12.3 临时目录建议

~~~text
cacheDir/
├── photo-drafts/<随机操作ID>/
├── import-staging/<随机操作ID>/
└── exports/<随机操作ID>/SilverPhone_联系人_时间.zip
~~~

所有目录由程序生成，不使用外部文件名作为目录。App 前台启动或新操作前做有界清理；活跃操作不清除；分享导出留够读取时间，不加 WorkManager 或后台常驻清理服务。

## 13. ZIP、JSON 与导入计划

### 13.1 组件职责

| 组件 | 职责 |
|---|---|
| BackupWriter | 读取一致快照，流式写规范 ZIP |
| BackupReader | 限制字节数、验证条目、严格解析 DTO、检查照片 |
| PhotoNormalizer | 统一图像规范并生成最终 JPEG |
| ImportPlanner | 根据来源、目标快照、模式输出新增／跳过／替换计划 |
| ImportCoordinator | 暂存、预览、确认、修订号校验和事务调用 |
| TransferUiState | 对用户展示真实阶段及数量 |

保持具体、小型类。不创建可插拔备份引擎、格式注册中心或未来同步协议层。

### 13.2 JSON

使用 kotlinx.serialization 的明确 DTO，设置 ignoreUnknownKeys=false、isLenient=false、coerceInputValues=false。协议字段名与 02 文档完全一致，不按 UI 名称自行改写。

字段解码后仍做业务校验；成功反序列化不等于电话号码、排序和照片引用合法。schemaVersion 只接受 1，不写 if 0/2/unknown 则猜测读取的路径。

### 13.3 导入计划

建议使用具体值对象：来源摘要、模式、expectedRevision、新增联系人列表、按原因分类的跳过项、替换旧数量、新数量、暂存资源标识。

计划不能包含 Activity、原始系统 Cursor 或完整 Bitmap 集合。正式提交只能消费已经通过校验且仍然有效的计划。提交时核对修订号，不直接相信预览时的数量。

### 13.4 安全和取消

严格实施 02 的 80 MiB ZIP、70 MiB 展开、1 MiB 清单、501 条目、单照片 128 KiB 等边界。流处理必须边读边统计；不能在读取全部数据后才检查大小。

优先使用 ZipInputStream 逐条处理和计数，将内容写入程序生成文件名的私有暂存区；不先无界枚举整个归档或把全部条目加载到内存。条目名称只用于白名单验证与清单关联，不直接成为落盘路径。后续预览和提交读取这些已验证暂存资源，不反复解压原文件。

防止 ZIP 路径穿越、重复条目、额外条目、图像解码膨胀。异常不吞掉，不将 CancellationException 包成成功结果。取消在事务提交前生效；已提交后不能再声称本次被取消而偷偷执行第二次。

## 14. 备份、日志和隐私

- 明确设置 android:allowBackup=false。
- 同时针对 API 23～30 配置 fullBackupContent 排除规则，针对 API 31+ 配置 dataExtractionRules 的云备份与设备传输排除。
- 联系人数据库、设置、照片与应用文件都在排除范围；缓存本身不作为系统备份来源。
- 不仅凭 allowBackup=false 宣称所有厂商设备迁移一定被禁用，官方说明了部分设备的区别。最终以合并配置与目标机验证为依据。[Android 自动备份说明](https://developer.android.com/identity/data/autobackup)
- 日志只写错误类型、操作阶段和数量；不记录完整姓名／号码、照片字节、可分享 URI 或完整导出清单。
- 测试 fixtures 使用合成联系人和自制图片，不能提交真实家属照片。
- 导出 ZIP 未加密；FileProvider 临时授权不能让已复制出去的文件自动失效。
- 不引入 SQLCipher、云密钥或自制加密协议。若以后明确提出加密备份，再另行制定用户密码和恢复规则。

## 15. 旧机资源控制

- 不依赖 Google Play 服务，应用本地功能在没有该服务的 Android 手机上仍可用。
- 不引入非必要原生图像库；不能只生成 arm64 包而遗漏用户需要的 32 位旧机。
- 若依赖 APK 中含 .so，检查实际 ABI、API 23 支持及面向新 Android 的 16 KB 页大小要求；没有原生库也应在交付记录中写明检查结果。
- 不用 largeHeap=true、不锁死竖屏、不关字体缩放来掩盖问题。
- 列表只查询元数据；图像按可见范围解码；ZIP 和图像处理不全部并行。
- JPEG BLOB 上限必须实际检查，避免大行和 CursorWindow 问题。
- 500 张图片不能同时进入一个 UI State、SavedStateHandle、Binder 参数或内存数组。
- 使用公开、维护中的 API；不要为新机功能给旧机留下无效按钮。
- 不检测设备厂家后接多套私有电话接口。

## 16. 异常建模

建立少量有业务意义的错误类型，例如：ValidationError、PermissionMissing、PhoneUnavailable、InvalidBackup、UnsupportedBackupVersion、CapacityExceeded、StorageFailure、StalePreview。

错误类型映射到资源字符串，不直接展示 exception.message。取消单独表示，不混成失败。

需要恢复的错误在页面持续显示；成功提示以实际完成程度为准：生成缓存、保存文件、打开分享、导入落库是不同结果。不能用一个通用“成功”覆盖全部情况。

## 17. 测试分层

### 17.1 JVM 业务测试

使用 JUnit 与 kotlinx-coroutines-test。重点验证：

- 姓名码点边界和号码规范化。
- 追加规则：同 ID、同号、来源内部共用号码、重复包、容量边界。
- 导入计划确定性、排序和修订号过期处理。
- 协议 DTO、版本、字段、ZIP 限制、路径白名单、大小及哈希。
- 拨号协调状态：一个事件只消费一次，拒绝／取消／重建不重播。

PhoneLauncher 在测试中是可记录调用的实现，所有自动化测试禁止拨打真实号码。

### 17.2 Room 仪器测试

在最低 API 上验证实际 SQLite／Room 行为：外键级联、事务回滚、排序交换、Flow 更新、128 KiB 图像读写及追加／替换原子性。

模拟替换中途抛出异常，比较旧联系人与照片的完整集合仍在。只测试 DAO 成功插入一条不足以证明导入安全。

### 17.3 Compose 与系统接入测试

- 点照片、姓名、底部操作区都映射同一联系人。
- 点击和滚动不混淆；连点不触发多次。
- 大系统字体和应用超大档下，关键元素不截断且可操作。
- 空状态、权限拒绝、错误恢复、选择器取消可完成。
- 页面返回、Activity 重建、进程重建不重放拨号效果。
- 选图后删除来源，持久化照片仍显示。
- A 导出／B 导入的真实文件往返，视觉与数据数量一致。

使用 AndroidX Test、Compose UI Test、必要的 UI Automator；不要为了测试增加远超应用本身的框架。

### 17.4 手工真机验证

实际电话和双卡依赖目标设备。使用测试人员明确允许的号码和接听者，验证直接拨出、系统取消／挂断、返回与权限撤销。不拨紧急号码，不自动轮询所有联系人。

旧机内存、厂商文件提供者、桌面图标主题、老人识别行为必须单独记录真机／用户证据；模拟器截图不能代替这些结论。

## 20. 禁止的实现方式

- 一个超大 MainActivity 同时写 UI、SQL、ZIP、权限和电话逻辑。
- 通过 ACTION_DIAL 冒充一步拨号；通过默认拨号器身份扩展范围。
- 只保存系统头像 URI，导出文件里仍是本机路径。
- 联系人入库后再独立逐张保存照片，允许半份成功。
- 复制 Room db 文件但遗漏 WAL，或把数据库当跨设备协议。
- 导入错误后只写日志、继续处理并显示全部成功。
- 每次打开应用弹出全部权限申请。
- 使用重型后台任务／服务器完成本来可在前台本地完成的工作。
- 为“以后可能需要”建立多租户、插件化存储、格式适配器体系。
- 用数据库删库重建解决错误；提供未需求化的历史迁移路线。
- 覆盖系统 fontScale、硬截断姓名、锁定窗口尺寸。
- 编造构建结果、模拟器截图、设备型号、真实通话或用户测试记录。

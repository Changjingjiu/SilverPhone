# SilverPhone · 设计规格（Design Specification）

来源：`00_使用说明与总控提示词.md`、`01_UI设计_AI提示词.md`、`02_软件逻辑_AI提示词.md`、
`03_软件功能_AI提示词.md`、`04_软件技术栈_AI提示词.md`。

说明：本任务**没有源视频**，全部约束来自上述四份 Markdown 文档，因此本文件只使用 `[S<编号>]`
（Spec 观测项）。不存在可引用的视频切片时间段，故不产生 `[D<编号>]` 行——写入无法校验的
视频时间戳等于编造证据。

每行是一条**可观察、可验证**的规格项，带实测或文档给定的数字。

---

## 一、颜色

[S01] BrandLime 桌面图标底 `#D6FF00`；Ink 深墨蓝听筒 `#172554`，二者对比度约 12.71:1。
[S02] 页面背景 Background `#F7F8FA`；卡片/表单/对话框 Surface `#FFFFFF`。
[S03] 主要文字 TextPrimary `#172554`；辅助说明 TextSecondary `#475569`，对页面底约 7.13:1。
[S04] 拨打 CallGreen `#146C43`，其上文字与听筒 OnCallGreen `#FFFFFF`，白/绿约 6.45:1。
[S05] 取消 CancelRed `#B42318`（描边+叉形+文字），白底约 6.57:1；DangerRed `#B42318` 用于删除/整体替换的实心按钮。
[S06] 输入框与按钮边界 Outline `#64748B`；键盘/无障碍焦点 Focus `#1D4ED8`。
[S07] 六个占位色固定为 LIGHT_BLUE `#DBEAFE`、LIGHT_AMBER `#FEF3C7`、LIGHT_PURPLE `#F3E8FF`、LIGHT_TEAL `#CCFBF1`、LIGHT_ROSE `#FFE4E6`、LIGHT_GRAY `#E2E8F0`，轮廓统一用 Ink `#172554`。
[S08] 固定浅色主题，关闭动态取色；不提供夜间/换肤开关。文字对比目标 ≥ 4.5:1，关键图形与控件边界 ≥ 3:1。

## 二、字体与字号

[S09] 应用倍率四档：标准 1.0、大 1.2、特大 1.4、超大 1.6；**默认 1.2（大）**。
[S10] 基准 sp（应用倍率 1.0 时）：页面主标题 32sp/Semibold、首页联系人称呼 26sp/Semibold、主要按钮 24sp/Semibold、表单与正文 22sp、辅助说明 18sp。
[S11] 应用倍率先乘基础 sp，再由系统 fontScale 解析；不得覆盖 LocalDensity 的 fontScale，不得重复相乘。
[S12] 字号作用于全部应用内页面（含对话框、错误说明、按钮）；不控制系统电话页、桌面图标、系统权限弹窗。

## 三、尺寸与触控

[S13] 常用主操作可视图形 40～48dp，随档位递增（40/48/56/64dp）；家属入口图形 ≥ 32dp。
[S14] 所有可点区域 ≥ 56×56dp；主要按钮高 ≥ 64dp；触控目标间距 ≥ 12dp。
[S15] 首页卡片间距 16dp、圆角 16dp；页面左右留白 16dp（极窄窗口 12dp，不压缩触控间距）。
[S16] 输入框高 ≥ 64dp，随多行内容增高；首页卡片整张可点，不是只有底部听筒可点。

## 四、页面树

[S17] 应用内页面：S01 亲人首页、S02 家属入口确认、S03 家属设置、S04 管理亲人、S05 添加/编辑亲人、S06 照片预览与调整、S07 从手机通讯录导入、S08 文件导入预览、S09 导出与结果、S10 字号设置、S11 拨号帮助/错误。
[S18] 系统页面：X01 系统电话界面（ACTION_CALL）、X02 系统文件/照片选择器（SAF）、X03 系统权限/分享界面。
[S19] 首页结构自上而下仅三项：标题“打电话”、家属设置入口、亲人卡片区；无底部导航、无广告、无搜索、无最近联系人。
[S20] 家属进入设置需两次点击：S01“家属设置” → S02“进入设置”；不使用密码、手势、算术题。

## 五、首页（S01）

[S21] 列数：可用宽度 < 360dp 单列；≥ 360dp 时**仅当**每列能容纳当前字号下 4 个汉字及内边距才用两列；任何情况最多两列，只纵向滚动。
[S22] 两列时照片为接近满宽方形，扣除内边距后约 ≥ 120dp；单列照片建议 ≥ 160dp。
[S23] 首页不显示号码、通话次数、新闻、天气、日期时钟、每日提示。
[S24] 空状态：大人物图形 + “请家人添加亲人” + 大按钮“家属设置”；不预置可拨打的示例联系人。
[S25] 读取失败态与空状态必须区分：失败显示“暂时读不到亲人信息”+ 重试，不显示空列表并建议重新添加。
[S26] 加载态保留页面结构，不显示假联系人。
[S27] 权限未开时仍显示联系人；点卡进入 S11 帮助，不悄悄换成另一套拨号操作。

## 六、拨号

[S28] 正常前提下，一次普通点击整张卡片即使用 ACTION_CALL + tel URI 发起请求；不增加本应用确认页、倒计时、长按、双击或号码选择。
[S29] 门闩：点击处理在主线程串行路径上先置门闩再异步检查；门闩关闭时忽略后续点击（包括另一联系人），不排队、不覆盖。
[S30] 附加 ≥ 1000ms 请求间隔，仅用于防止同一手势重复，不在 UI 显示倒计时。
[S31] Composable 重组、Flow 再发值、横竖屏变化、Activity 重建均不得重新发出 Intent。
[S32] 交给系统后若无窗口切换，3 秒后仅解除门闩，不推断接通或失败，不自动重发。
[S33] 状态机：READY → CHECKING → DISPATCHING → HANDED_OFF；异常分支 HELP / ERROR，均不自动拨打旧联系人。
[S34] 红色“取消”只取消尚在应用内的操作，电话交出后不能挂断系统通话。

## 七、联系人数据

[S35] Contact 字段：id（小写规范 UUID v4）、displayName（1～12 个 Unicode 码点）、phoneNumber（规范化）、sortOrder（0 起连续整数）、placeholderColor（六枚举之一，默认 LIGHT_BLUE）、photo（可空）。
[S36] 号码规范化：去首尾空白 → NFKC → 去除普通空格/NBSP、短横线、左右圆括号 → 开头可一个 `+`，之后 3～20 位 ASCII 数字；拒绝内部换行、字母、多 `+`、`/`、`*`、`#`、`,`、`;` 等。
[S37] 不自动加 `+86`，不删除用户填写的国家码，不裁成 11 位。
[S38] 照片：正方形、边长 ≤ 512px、单张 ≤ 128KiB（131072 字节）JPEG，Room BLOB 长期保存，移除原 EXIF/GPS/文件名。
[S39] 照片编码回退序列：512/质量 82 → 512/70 → 384/70 → 256/70，取首个 ≤ 128KiB 的结果；仍超限则报错，不无限循环。
[S40] 外部原始照片上限：文件 20MiB、像素 2400 万；必须先读尺寸再采样解码。
[S41] 容量：本地联系人 ≤ 500；导入文件内联系人 ≤ 500。
[S42] 同号/同名允许存在（共用座机）；号码建普通索引不建唯一索引。
[S43] 数据库三张表：contacts、contact_photos（contactId 主键 + 外键 ON DELETE CASCADE）、app_settings（id 固定 1）。
[S44] app_settings.fontPreset 默认 LARGE；contactsRevision 为非负 Long，联系人/照片/顺序事务成功后 +1，字号调整不增加。
[S45] 数据库 version = 1，exportSchema = true；不使用 fallbackToDestructiveMigration。

## 八、交换文件协议 v1

[S46] 容器为普通未加密 ZIP，仅含 `manifest.json` 与 `photos/<contactId>.jpg`；文件名 `SilverPhone_联系人_YYYYMMDD_HHmmss.zip`。
[S47] manifest 字段：format 固定 `silverphone-backup`、schemaVersion 整数 1、exportedAt ISO 8601 UTC、appVersion、contacts 数组（1～500，按 sortOrder）。
[S48] photo 对象字段：path 严格等于 `photos/<本联系人id>.jpg`、mimeType 固定 `image/jpeg`、byteCount 1～131072、sha256 为 64 位小写十六进制。
[S49] 边界：ZIP 实际大小 ≤ 80MiB、解压累计 ≤ 70MiB、manifest ≤ 1MiB、条目 ≤ 501、单张归档照片 ≤ 128KiB；边读边计数，不信任声明值。
[S50] 拒绝：重名条目、额外条目、未声明照片、声明但缺失、绝对路径、`..`、反斜杠、盘符、嵌套 ZIP、加密包、坏 CRC、未知 schemaVersion。
[S51] 追加模式（默认）判定顺序：同 id 命中 → 跳过；否则同规范化号码命中 → 跳过；否则新增且保留来源 id/称呼/号码/颜色/照片。
[S52] 比较集合恒为预览开始时的原始目标快照 T，不随逐条加入而变化；因此空目标机可完整保留来源中不同 id 但共用号码的人。
[S53] 新增数为 0 时不写库、不增加修订号；结果文案为“没有新增，已保留现有亲人”。
[S54] 替换模式需显式选择并二次确认，同事务删除全部旧联系人/照片并写入完整来源集合；字号档位保留，修订号 +1。
[S55] 预览记录 expectedRevision，提交时在事务内比对；不一致则停止提交并重新生成预览。

## 九、权限与隐私

[S56] Manifest 仅声明 CALL_PHONE（运行时申请）与 READ_CONTACTS（按功能运行时申请）；不声明 INTERNET、WRITE_CONTACTS、READ/WRITE_CALL_LOG、READ_PHONE_STATE、CAMERA、存储权限、POST_NOTIFICATIONS、SYSTEM_ALERT_WINDOW。
[S57] 不成为默认拨号器，不实现 InCallService，不请求 RoleManager 电话角色，不使用 AccessibilityService 自动操作系统电话按钮。
[S58] `android:allowBackup="false"`，并同时提供 fullBackupContent（API 23～30）与 dataExtractionRules（API 31+）排除规则。
[S59] FileProvider exported=false、grantUriPermissions=true，仅暴露 `cacheDir/exports/`；不暴露 cache 根、files 根或数据库。
[S60] 日志不写完整姓名/号码、照片字节、可分享 URI 或完整导出清单。
[S61] 导出文件未加密，页面提示“文件里有亲人的姓名、电话和照片，请只发给信任的人”。

## 十、技术基线

[S62] minSdk 固定 23（Android 6.0）；compileSdk/targetSdk 取实施时稳定的 36；不使用 tools:overrideLibrary 抬高下限。
[S63] 栈：Kotlin、Jetpack Compose、Material 3、Room、Coroutines+Flow、ViewModel+StateFlow、Navigation Compose（单 Activity）、kotlinx.serialization、java.util.zip、Coil 3（仅本地）、CanHub CropImageView（仅 S06）、ExifInterface、SAF + Activity Result API、FileProvider。
[S64] 一个 `:app` 模块，包内分层；依赖注入用简单构造注入 + AppContainer，不引入 Hilt/Koin。
[S65] navigation-compose 固定 2.9.8：2.10.x 的 AAR 声明 minSdk 24，会破坏 [S62] 的 API 23 合同。
[S66] Room 2.8.5、Compose BOM 2026.08.00（ui/foundation/material 1.12.0、material3 1.4.0）；实测这些 AAR 的 minSdk 均为 23。
[S67] 不使用 largeHeap、不锁死竖屏、不覆盖系统 fontScale、不硬截断姓名。

## 十一、验收要点

[S68] AC04：点照片、点称呼、点绿色区域三种位置触发同一号码、同一次请求。
[S69] AC05：连点同一张卡 10 次、旋转、Activity 重建，均不产生重复拨号。
[S70] AC11：添加照片后删除源相册文件、重启应用，头像仍显示。
[S71] AC15：A 导出 → 空 B 导入，字段、照片视觉内容与顺序一致，B 不访问 A 的 URI。
[S72] AC17：同一文件连续追加 3 次，第二次起新增 0，无重复卡、无改序。
[S73] AC19/AC20：替换中途失败或坏文件时，旧联系人与旧照片完整保留，数据库不变。
[S74] AC26：API 23 安装并可完成核心全流程。
[S75] AC28：杀进程后只见完整旧集合或完整新集合，且不恢复自动呼叫。
